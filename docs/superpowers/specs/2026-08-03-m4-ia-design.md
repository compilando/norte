# M4-IA remainder: AI rename over the wire + semantic index

- Date: 2026-08-03
- Status: approved (brainstorm with oscar)
- Builds on: ADR 0031 (AI subsystem), ADR 0034 (FTS5 index), spec §9.

## Context

ADR 0031's A1 (crate `norte-ai`), A2a (`[ai]` config + core gate) and A2b
(`Engine::ai_rename_plan` + embedded CLI command) already shipped
(commits 21f9412..15d83c7). `norte-index` exists as the FTS5 name index
(ADR 0034) with `index.build`/`index.query` on the wire (proto 0.25.0).
Current protocol version: 0.31.0.

What remains of M4-IA, and what this spec covers:

1. **IA-1**: `ai.rename_plan` on the wire + reviewable-plan UX in TUI and GUI.
2. **IA-2**: semantic index (A3) — embeddings via the configured provider,
   `index.embed` task, `index.search_semantic`, TUI/GUI search UX.

Decisions taken during brainstorm:

- `ai.rename_plan` is a **plain request** cancellable via `rpc.cancel`, not a
  Task. Precedent: the policy Ask already suspends a serial dispatch; #64/#72
  cover peer death and cancel during an in-flight dispatch. Cancellation is
  drop-based: cancelling the dispatch future drops the `ChatStream`, which
  aborts the HTTP request. The connection's serial dispatch blocks during the
  model call; the UX is modal anyway.
- Embeddings are a **separate task `index.embed`**, not a flag on
  `index.build`. The FTS5 name build stays fast and free of the AI gate;
  embedding is opt-in, AI-gated, and reuses the already-indexed `files` rows.
- GUI is **in scope** (norte-gui builds outside the workspace; it consumes the
  same wire).
- Rename v1 operates on the **whole directory** (current engine signature).
  Rename over the first-class selection (#103) is deferred to an issue.

## IA-1: AI rename over the wire

### Wire (proto 0.32.0, protocol-guardian review)

- New method `ai.rename_plan`:
  - `AiRenamePlanParams { dir: String, instruction: String }` — `dir` in
    `VPath` wire encoding.
  - `AiRenamePlanResult { entries: Vec<{from: String, to: String}> }` —
    basenames, guaranteed UTF-8 (the engine refuses hostile names fail-loud
    before anything reaches the provider).
- New goldens in `methods.json`; N-1 window shifts to 0.31.x.
- No new error types: `PolicyDenied` (AI gate), `Unsupported` (no provider),
  and the existing wire taxonomy for provider failures suffice.

### Daemon

- `norte daemon run` builds the AI provider at startup from config
  (`resolve_and_build`, the same path the CLI uses per invocation) and calls
  `set_ai_provider`/`set_ai_config`. No `[ai]` config → `Unsupported`,
  fail-closed.
- Handler dispatches to `engine.ai_rename_plan(dir, instruction)`. `rpc.cancel`
  works unchanged (drop-based, see above). The policy gate applies through the
  engine as usual; an out-of-scope agent sees `PolicyDenied`.

### TUI

- New verb (command palette / key) on the active pane's directory →
  instruction input → spinner (Esc cancels via `rpc.cancel`) → plan modal:
  one `from → to` pair per line, hostile-safe rendering (encoding-auditor
  conventions: masking + middle ellipsis, one path per line).
- Confirm applies N ordinary `fs.move` operations (journal + undo + policy —
  nothing new to govern). Partial failure is reported; each applied move is
  journaled; session undo reverts what was applied.

### GUI

- Same flow through its daemon client: instruction dialog → reviewable plan →
  confirm. Reuses the GUI's existing modal machinery.

### CLI

- Already works embedded; no changes.

## IA-2: semantic index

### Schema (additive, same SQLite DB as the FTS5 index)

```sql
CREATE TABLE embeddings (
    file_id   INTEGER PRIMARY KEY REFERENCES files(id) ON DELETE CASCADE,
    model     TEXT NOT NULL,      -- id of the model that produced the vector
    dim       INTEGER NOT NULL,
    vec       BLOB NOT NULL,      -- f32 little-endian, dim * 4 bytes
    text_hash BLOB NOT NULL       -- sha256 of the text prefix that was embedded
)
```

- Invalidation: re-embed when `text_hash` changed or `model` differs from the
  configured one. A stale-model vector counts as absent: search ignores it,
  `index.embed` regenerates it.
- Deleting a `files` row cascades to its embedding.

### Task `index.embed` (engine, cancellable — rule 3)

1. Requires a prior `index.build`; without one → typed, actionable error
   ("run index.build first").
2. Reads the root's `files` rows (kind = file), filters: size cap, text
   heuristic (extension-based in v1), and **excludes `denied_prefixes` before
   reading anything**.
3. Per file: reads a bounded prefix (32 KiB) through the engine's providers
   (never direct FS), sha256s it, skips if hash+model unchanged.
4. Embeds in batches of 16 via the `embed_provider` — full AI gate (enabled,
   local-only, denied). Local Ollama is the expected default.
5. Cancellation token checked per file; clean-cancellation test required.

- Progress via ordinary task notifications. New `TaskKind::Embed` (N-1
  degrades to `Unknown`, same precedent as `Index`).

### Config

- `[ai] embed_provider = "<name>"` (`Option`, later-layer-wins, same merge as
  `rename_provider`). Caps (32 KiB prefix, batch 16, k ≤ 100) are hard-coded
  in v1.

### `index.search_semantic` (plain request)

- Params `{ query, root?, k }` (k clamped to ≤ 100) → one embed call for the
  query → brute-force cosine scan in Rust over the root's vectors (dim
  mismatch / stale model ignored) → hits `{ path (wire encoding), score }`.
- No ANN (per ADR 0031: only if a real corpus proves it necessary).

### Wire

- Own bump when it lands (0.33.0): `index.embed`, `index.search_semantic`,
  `TaskKind::Embed`, goldens.

### TUI / GUI

- "Semantic search" entry (palette / verb) → query input → hostile-safe result
  list → Enter navigates to the file. GUI runs the same flow over the wire.

## Errors

- The existing `AiError` → wire mapping (used by rename) is reused by embed.
- `RateLimited` during an embed batch: bounded backoff retry (3 attempts)
  inside the task, then the task fails — it never hangs.
- An invalid model reply for rename is a typed error with zero mutation
  (already built that way).

## Testing (no network in the gate, ever)

- Deterministic `FakeEmbedProvider` (vector derived from a hash of the text)
  as a norte-ai test utility (testkit does not depend on norte-ai).
- Cosine correctness golden (known vectors → expected order).
- `index.embed`: clean cancellation (rule 3), skip on unchanged hash, re-embed
  on model change, denied_prefixes excluded BEFORE reading (test: the fake
  provider records what it received).
- Wire: new methods.json goldens, params/results round-trip.
- TUI: hostile plan render test (corpus) + hostile semantic-hit render test.
- Daemon: `ai.rename_plan` over UDS with a fake provider (norte-ai's fake HTTP
  server already exists), including `rpc.cancel` mid-call.
- E2E: reviewable rename end-to-end in-process + semantic search over a small
  corpus.

## Security and privacy

- Nothing leaves the process without passing the gate (enabled + local_only +
  denied_prefixes); embed filters paths before reading content.
- What leaves the machine: rename = basenames + instruction; embed = 32 KiB
  content prefixes; search = the query. Documented and surfaceable in the UI
  (spec §9: the UI shows exactly what leaves).
- Secrets: existing chain (env → keyring → age), resolved by the daemon, never
  logged.
- Reviewers per sub-block: protocol-guardian (bumps), security-reviewer
  (embed sends file content off-machine), encoding-auditor (plan/hit
  rendering), rust-reviewer.

## Sequencing and exit criterion

- **IA-1** rename wire + TUI (+ GUI) → bump 0.32.0, reviewers, `just ci`.
- **IA-2** semantic (schema + task + search + TUI/GUI) → bump 0.33.0,
  reviewers, `just ci`.

**M4-IA exit criterion:** from the TUI against the daemon, a user renames a
directory with AI through a reviewable plan with undo, and semantic search
returns relevant files from a corpus indexed with local Ollama — all with an
explicit `[ai] enabled = true`; nothing leaves the machine under the default
config.

## Deferred

- Rename over the first-class selection (#103 machinery) — issue on landing.
- ANN index, chunked embeddings (beyond one prefix per file), content-type
  sniffing beyond extensions, Gemini/Vertex providers.
