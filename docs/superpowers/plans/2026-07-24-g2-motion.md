# G2 — motion (opt-in) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Opt-in motion for the GUI — CRT flicker, cursor blink, and `reduce_motion` accessibility override — with the frame loop alive ONLY while an animated effect is active and the window focused.

**Spec:** G2 in `docs/superpowers/specs/2026-07-23-gui-visual-plugins-design.md:146-159`; ADR 0036 pre-authorizes the v1.1 keys under the per-key-lenient contract (adr:157-160).

**Verified GPUI facts (rev f14fea9):** `Animation{duration,oneshot,easing}` + `.repeat()` + `pulsating_between(min,max)` easing (animation.rs:14-289); `with_animation` self-requests frames and **natively honors `cx.reduce_motion()`** (animation.rs:161-168, renders one static frame and stops); `App::set_reduce_motion` (app.rs:1016) — set once, every animation respects it; `Window::request_animation_frame` (window.rs:2229; doc says gate on reduce_motion when calling directly); `Window::is_window_active` (window.rs:2352) pollable in render, and focus changes force a refresh (window.rs:1589-1610) — no public activation observer at this rev, POLLING in render is the sanctioned shape. norte-gui: canvas paint closure does NOT self-request frames — flicker must request from `render()`; `paint_scanlines`/`paint_vignette` opacity fields ready to scale (main.rs:2370/2412); cursor row bg at render_row main.rs:1482-1489; effects.rs KNOWN_KEYS=4 + decode fns are the extension template; UiSection has no reduce_motion yet (schema golden will regenerate).

**Decisions locked:**
1. Schema v1.1 keys (lenient, per-key degrade, ADR 0036 contract): `flicker = { strength = 0.05 }` clamp [0.0, 0.15] (TINY — a11y; default 0.05), `cursor_blink = true` (bool), `fade_ms = 120` clamp [0, 400] — **fade DEFERRED**: implementing modal/pane fade touches every overlay path for marginal payoff; v1.1 PARSES fade_ms (schema complete per spec) but the GUI does not yet animate fades — documented in ADR amendment + CHANGELOG ("parsed, not yet rendered"). Flicker + cursor_blink ship.
2. `[ui] reduce_motion: Option<bool>` in norte-config (System+User layers honored; Project too — presentation, same class as theme/lang). Default false (platform hint: GPUI exposes no such hint at this rev — document "else false" branch taken). GUI startup: `cx.set_reduce_motion(value)` once — GPUI then kills all `with_animation` motion for free; the direct `request_animation_frame` path ALSO gates on `cx.reduce_motion()` (belt).
3. Frame loop: at the END of `render()`: `if motion_active && window.is_window_active() && !cx.reduce_motion() { window.request_animation_frame(); }` where `motion_active` = effects has flicker OR (cursor_blink AND a cursor row is visible). Flicker phase computed from a stored `Instant` epoch (elapsed-based sine — NO Date::now concerns, std Instant); scanline/vignette opacity scaled by `1.0 + strength*sin(phase)` clamped to the static caps. Cursor blink via `with_animation` + `pulsating_between` on the selected row bg alpha (GPUI-native path, reduce_motion free).
4. Perf: flicker recomputes ONE f32 per frame and repaints the existing canvas (bounded quads); no per-row work added. Blur/none → no frame request → event-driven again (spec's timer-lifecycle requirement satisfied by construction — poll-in-render + focus-refresh).
5. retro-crt presets: add `flicker = { strength = 0.05 }` + `cursor_blink = true` to both retro presets ([effects] blocks) — the flagship look gets motion by default; other presets untouched.
