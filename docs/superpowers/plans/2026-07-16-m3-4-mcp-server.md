# M3-4 — norte-mcp server (puente MCP → daemon) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Un agente MCP (Claude Code, Codex CLI…) gestiona archivos A TRAVÉS de norte — daemon con journal+policy, scope concedido por humano, regla `ask` con aprobación interactiva, y undo de la sesión completa del agente — cerrando el criterio de salida de M3.

**Architecture:** `norte-mcp` es un PUENTE de proceso separado: habla MCP (JSON-RPC 2.0 NDJSON sobre stdio) con el agente y reenvía cada tool al daemon por UDS como cliente con `agent_session` — el enforcement (scope, policy, ask, journal) vive ÍNTEGRO en el daemon (regla 9); el puente no toca el FS ni decide nada. Sin dependencia `rmcp` en v1: el framing NDJSON y el JSON-RPC ya viven en `norte-proto::wire` (regla 8; HTTP transport = deuda). El daemon pasa a ser el dueño único del journal (deuda M3-1b) y `session.undo` (proto 0.12.0) permite a un humano deshacer la sesión de un agente (split selector/ejecutor, deuda M3-2).

**Tech Stack:** Rust, `norte-proto::wire` (NDJSON JSON-RPC), `norte_core::daemon::Client`, clap (CLI), nextest. Reviewers: **protocol-guardian OBLIGATORIO** (Task 3), **security-reviewer OBLIGATORIO** (Tasks 4 y 5), rust-reviewer por task, encoding-auditor en Task 5 (paths por el puente).

**Nota de threat model:** el agente MCP es un proceso local del mismo uid — la policy es un guardarraíl para agentes que COOPERAN, no un sandbox contra código hostil local (spec §14, igual que M3-3b). El valor es: todo pasa por policy+journal+audit, nada toca el FS "por fuera".

- [ ] **Step 1: ADR 0024** — decisiones y por qué:
  - **Puente separado, no servidor MCP embebido en el daemon**: el daemon habla UN protocolo (norte); MCP es un dialecto de cliente. El puente se conecta con `agent_session` → el daemon fija `Actor::Agent` server-side y TODO el enforcement (scope/policy/ask/journal) ocurre allí. El puente es intercambiable y no-privilegiado.
  - **Sin `rmcp` en v1** (regla 8): MCP stdio = JSON-RPC 2.0, un mensaje por línea (NDJSON) — exactamente `norte-proto::wire` (`FrameDecoder`/`encode_frame`, fuzz ya existente). Un SDK completo aporta transporte HTTP/SSE y macros que v1 no usa, y costaría revisión de superficie. Deuda anotada: transporte streamable-HTTP cuando haya demanda (ahí sí, reevaluar rmcp).
  - **Versión MCP objetivo**: `2025-06-18` (la respondemos fija; el handshake MCP tolera que el server conteste su versión soportada).
  - **Tools v1 = lo que el wire ya ofrece**: `list_dir, stat, read_file, copy, move, delete, task_status, request_scope`. Sin `write_file`/`mkdir`/`search` (no existen en el protocolo hoy; entrarán con su método de wire, no como atajo del puente — regla 9).
  - **Borrado agéntico**: el tool `delete` default `trash` (spec §10: "los borrados agénticos van SIEMPRE a trash/staging"); `permanent` existe pero policy decide (ask/deny).
  - **Daemon dueño único del journal** (cierra deuda M3-1b): `norte daemon run` abre `SqliteJournal` en `config_dir()/journal.db` + instala `ScopedPolicy` (`policy.toml`, ausente = sin reglas = fail-closed para agentes) + `DaemonApprovalResolver`. Los modos embebidos (TUI/CLI sin daemon) siguen SIN journal (single-writer, spec §4).
  - **Undo humano de sesión de agente**: split selector/ejecutor en el engine (deuda M3-2) + método de wire `session.undo` (proto 0.12.0), solo conexiones User.

```rust
/// `session.undo` (M3-4): un HUMANO deshace la sesión completa de un agente.
/// Target = `Agent{session}` (selecciona las entradas del journal), ejecutor
/// = `User` (pasa el gate y firma las compensaciones): el undo no depende de
/// que el scope del agente siga vivo. Solo conexiones User — un agente no
/// deshace a otros (la suya propia entrará como tool si hace falta: deuda).
#[tracing::instrument(skip_all, fields(session = %p.session))]
async fn handle_session_undo(
    actor: &Actor,
    p: methods::SessionUndoParams,
    shared: &Arc<Shared>,
) -> Result<serde_json::Value, RpcError> {
    if !matches!(actor, Actor::User) {
        return Err(RpcError::protocol(
            codes::INVALID_REQUEST,
            "only a human (non-agent) connection may undo an agent session",
        ));
    }
    if !valid_agent_session(&p.session) {
        return Err(RpcError::protocol(
            codes::INVALID_PARAMS,
            "session must be 1..=64 chars of [A-Za-z0-9._-]",
        ));
    }
    let target = Actor::Agent { session: p.session };
    let (handle, _report) = shared
        .engine
        .undo_session_for(&target, Actor::User)
        .await
        .map_err(RpcError::from)?;
    // Registra como cualquier task (broadcast de progreso, cancelable), pero
    // el result lleva su propio tipo de wire.
    let v = register_task(shared, handle)?;
    let r: methods::FsTaskResult =
        serde_json::from_value(v).map_err(|e| RpcError::protocol(codes::INTERNAL_ERROR, format!("shape: {e}")))?;
    to_value(&methods::SessionUndoResult { task_id: r.task_id })
}
```

```rust
/// Sirve MCP por stdio hasta EOF (el agente cierra el pipe al terminar).
/// Un mensaje por línea (NDJSON, como el transporte stdio de MCP).
///
/// # Errors
/// I/O de stdio o conexión inicial con el daemon.
pub async fn serve_stdio(socket: &std::path::Path, session: &str) -> Result<(), BridgeError> {
    use tokio::io::{AsyncBufReadExt, AsyncWriteExt, BufReader};
    let mut bridge = Bridge::connect(socket, session).await?;
    let stdin = BufReader::new(tokio::io::stdin());
    let mut stdout = tokio::io::stdout();
    let mut lines = stdin.lines();
    while let Some(line) = lines.next_line().await? {
        if line.trim().is_empty() {
            continue;
        }
        for out in bridge.handle_line(&line).await {
            stdout.write_all(out.as_bytes()).await?;
            stdout.write_all(b"\n").await?;
            stdout.flush().await?;
        }
    }
    Ok(())
}
```

`BridgeError` con `thiserror` (Io, Daemon(ClientError)). OJO regla 10: `tracing` del puente va a stderr o a fichero, JAMÁS a stdout (corrompería el transporte MCP) — no instales subscriber aquí; lo hace la CLI (Task 6) apuntando a stderr.
