### Task 0.2 — CRLF filename fixture — `done` (see git log)

Landed as `control_crlf` (`a\r\nb`) in `names.json`; the provider contract
round-trips it on mem/local and the FTP guest rejects it as `InvalidPath`
(test already existed in `ftp_provider_contract.rs`, probe `x\r\nDELE victima`).
**Finding:** the FTP provider is a WASM guest at
`norte-plugin-host/examples-wasm/ftp-provider`, NOT a workspace member, with
its own (gitignored) lock — `cargo deny` never sees its `suppaftp`. The
embedded `norte-core/resources/ftp-provider.wasm` was built 2026-08-15 with
10.0.1 and was rebuilt here with 10.0.2 (`just build-ftp-wasm`, needs
`rustup target add wasm32-wasip2`). See task 4.7.

Rule: a bug gets a failing test first, and encoding/path regressions get a
corpus fixture. Add to `norte-testkit`'s hostile corpus a name containing
`\r\n` (`/fixture` skill). Then a test in `norte-connect/tests/ftp.rs` (or
`norte-core` FTP plugin tests) that sends that name through the FTP path and
asserts the control channel saw ONE command. Reviewer: `encoding-auditor`.
If the fake FTP server there cannot observe the control channel, say so in
the status line and land the corpus fixture alone.

### Task 1.2 — TUI `dispatch()` and `run()` — `dropped after reading`

`dispatch.rs` says it in its own header: a flat `match` of 109 arms, one to
three lines each, kept flat on purpose because splitting an exhaustive table
by theme trades one compiler-checked table for several kept in sync by hand
— the same argument this repo already wrote for `server.rs`. `run()` is a
five-arm `select!`; the 380-line `tick` arm is a flat schedule of harvests
that already delegate to `jobs::harvest_*`, and extracting the schedule into
a function would need a struct for its dozen locals, which is a design round,
not debt. Nine earlier rounds took the depth out; what is left is vocabulary.
The audit's «800 lines» measured the wrong thing.

Original spec kept for the record:

Postmortems of the two previous rounds are in git history:
`git show a12a57f5 -- docs/superpowers/plans/2026-08-20-tui-prompts-and-run-loop.md`
(section "Lo que sigue sin hacerse") and the `2026-08-20-tui-app-impl-split.md`
of the same tree. Their finding stands: turning `run`'s 19-branch `else if`
chain into an overlay-precedence table changes `await` order inside a
23-arm `tokio::select!`. Do `dispatch()` first (a match over `Action`,
splittable per family without ordering risk); leave `run()` for last and
only with the parity tests as oracle.

### Task 1.3 — `server.rs` dispatch tables — `done as audit, small change`; catalogue exists upstream (ADR 0089)

Read both matches. They are already thin routers: every arm is either one
call to a `handle_*` fn or a 7–25 line `parse → gate → engine → register`
block. A method→handler table would trade exhaustiveness and inline-visible
gates for indirection, and the property the spec cared about — no method
skips policy — is not enforced by the router at all: it is the engine's
`*_as(actor)` API plus `read_gate`. Only change: the three repeated
«humans only» checks (`ai.rename_plan`, `index.embed`,
`index.search_semantic`) became `human_only(&actor)?`, same error, same
rule. The «no method catalogue» observation was already false on `main`: ADR 0089
added one so that forgetting a surface turns red.

Original spec kept for the record:

`dispatch_fs_task` (335 lines) and `dispatch` (196) are one match each
over 69 method names. Replace with a method→handler table so that a new
method cannot skip auth/policy by omission. Reviewer: `protocol-guardian`
(mandatory: JSON-RPC handlers) + `security-reviewer`.

### Task 2.1 — core — `done` (see git log)

Triage of the 38 `sleep()` lines in `norte-core/tests`: 26 are bounded polls
(`while !cond { assert!(now < deadline); sleep(…) }`) — they wait, they do
not race, left alone. 2 are fixtures (fake AI delay, scheduler occupancy).
The real races were 7 «sleep N ms then cancel, expect `Cancelled`» tests
and 2 fixed waits in `daemon.rs`:

- 5 cancel tests on `Engine::new()` (no sqlx) now run `start_paused = true`:
  the MemProvider's injected latency is on tokio's clock, so the order is
  deterministic and no wall clock is involved.
- 2 cancel tests with the sqlx journal (`undo.rs`, `engine_sync_apply.rs`)
  cannot pause: sqlx's pool times out (`PoolTimedOut`) when tokio
  auto-advances. Window widened 40 → 200 ms per op (50x over the 15 ms
  sleep). A deterministic fix needs a testkit gate for mutations like
  `hold_copy_native`; noted for a later wave.
- `fs_list_ttl_expira_el_listado`: fixed 400 ms after a 150 ms TTL → poll
  until `CursorExpired`, 5 s deadline.
- `request_scope` dies-with-connection: the 300 ms stays. No read-only
  observable exists for a pending scope request (`policy.pending` lists
  Asks) and probing with `grant_scope` would consume a live one. Needs a
  wire addition; out of scope.

Original spec kept for the record:

Replace waits-for-another-task with `Notify`/channels, and timing
assertions with `tokio::time::pause()` + `advance`. Keep a sleep only where
it is the thing under test (a debounce, a deadline) and say so in a comment.
`just t norte-core`. Reviewer: `test-engineer`.
