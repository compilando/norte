# Phase 3 report — UI strings outside Fluent

Source: section 3 of every T*.md report in this directory. Verified against
current code with `rg` (identifiers had moved since the reports were
written); a few strings the reports missed were found this way and fixed
too (noted below).

## Decisions applied

1. **norte-cli**: clap `///` help text (`main.rs`, `theme.rs`) and the CLI's
   `bail!`/`anyhow!`/`.context()`/raw `eprintln!` diagnostics → **English
   inline** (same convention as `ntc --help`).
2. **norte-gui-tauri `startup.rs` `USAGE` banner** → **English inline** (per
   its own `TODO(translation)`).
3. Everything else a user sees was supposed to go to Fluent (add to both
   `en.ftl`/`es.ftl`) — but nothing in scope qualified (see "Nothing went to
   Fluent" below).

## Strings translated

### `crates/norte-cli/src/main.rs` — English inline
Whole clap-derived surface: `Cli`'s `about`/fields, every variant and field
doc in `Cmd`, `SyncModeArg`, `AiCmd`, `IndexCmd`, `AuditCmd`, `AuditFormat`,
`PluginCmd`, `McpCmd`, `PolicyCmd`, `DaemonCmd`, `SymlinksArg` (this is the
literal `norte --help` output). Also: the `disable_help_subcommand` design
comment (not user-visible, but part of the same block T21 had deferred
whole); `exec_frontend`'s two `.context()` messages ("could not run
`{bin}`…"); `warn_line`'s hardcoded `"aviso: {phrase}"` prefix → `"warning:
{phrase}"` (this one bypasses Fluent regardless of the phrase's own language
— found during verification, not in T21's report).

### `crates/norte-cli/src/theme.rs`
Already English (translated in an earlier commit; T21's report was stale
from before the branch's final commits). No changes needed.

### `crates/norte-cli/src/cmd/daemon.rs` — English inline
`.context("resolución del socket/exe")` (×2), `.context("el puente MCP
terminó con error")`, `.context("no hay daemon en marcha")`,

The progress line's hardcoded `"entradas"` → `"entries"` (two call sites).

### `crates/norte-cli/src/doctor.rs` — English inline
Six `Finding.detail` format strings that print raw or serialize under
`--json`, bypassing Fluent: the layout-fallback sentence
(`"...(se arrancará con «orthodox»)"`), and five `[ui.columns]`/
`[ui.columns.spec]` diagnostics (`columns-bad-id`, `columns-plugins-over-cap`,
`columns-attrs-over-cap`, `columns-attr-id-not-wire-safe`, `columns-bad-spec`).
T21 only reported two of these (the layout one and `columns-attr-id-not-
wire-safe`); the other three were found during verification. Checked: no
test or golden asserts the translated prose — the column tests assert only
the interpolated raw ids (`"sise"`, `"plugin:p/c8"`, `"mem.a16"`, `"mtime"`).

### `crates/norte-gui-tauri/src/startup.rs` — English inline
The whole `USAGE` `--help` banner (was flagged `TODO(translation)` by T20
and reconfirmed stale-Spanish by T26b). Removed the now-obsolete
`TODO(translation)` comment along with it. No test asserts its content.

### `crates/norte-core/src/embedded.rs` — English inline (reasoned decision)
`NoJournal::text()`'s two leaf strings (`Busy`/`Failed`, #167/#178). Not in
decision #1's literal list (it's `norte-core`, not `norte-cli`), but its own
rustdoc says it explicitly: *"The phrase for the human, untranslated. It's
the one for the log and for the CLI... unlike its sibling
[`on_journal_recovered`/`on_journal_squatted`], which route through
Fluent."* `crates/norte-cli/src/main.rs`'s `JournalWarningStderr` doc
comment says the same from the call site. Since this text is designed to be
a single fixed language regardless of locale (same role as a CLI
diagnostic), I translated it in place rather than inventing a Fluent key
that the design explicitly avoids. No test asserts the exact text.

### `plugins/git-panel/src/guest.rs` — English inline (reasoned decision)
Six painted strings T25 reported (`"sin permiso de lectura"`, `"aquí no hay
un repositorio"`, `"rama "`, `"(HEAD desprendido)"`, `"sin commits
todavía"`, `"últimos movimientos"`, `"[registro]"` — seven, one was a footer
+ label pair I'm counting together). **Not routed to Fluent**: this is a
`#![no_std]`-style WASM guest (`extern crate alloc`) compiled to
`wasm32-wasip2`; its only host imports are `host_config`/`host_log`/
`location` (checked the `.wit` — no locale/Fluent import exists in any
plugin world, and no other plugin does i18n). Adding one would mean a WIT
break across every plugin world (ADR territory, out of scope for a
mechanical translation pass), so I translated the literals in place, same
treatment as the CLI. Verified this doesn't collide with the "rama main"
fixture strings in `norte-ui-host`'s and `norte-gui-tauri`'s tests/goldens
(`tests/controller/plugin_panes.rs`, `tests/golden/updates.json`,
`ui/tests/render.test.ts`) — those are independent hand-written fixture
data simulating *a* panel, not calls into this plugin's compiled `.wasm`,
so they're unaffected and correctly out of scope (test data).

### `plugins/git-panel/plugin.toml`, `plugins/git-status/plugin.toml` — English inline
Not reported by T25 under §3, but the same category: plugin manifest
`description` fields are shown to the user in the plugin manager and don't
go through Fluent. Every other plugin's `plugin.toml` was already English;
these two were the only stragglers. Translated all five description
strings. No test asserts their exact text.

## Left alone (reported, not touched)

- **`crates/norte-frontend/src/keymap/chord.rs`'s `spanish_name`** (T18):
  genuine `Lang::Es` localized chord-display output (`"Mayús"`, `"Intro"`,
  `"Retroceso"`, …), gated behind `CHORD_LANG == Lang::Es`. This is real
  product behavior, not code-Spanish — confirmed by reading the function and
  its call site (`pretty_token`).
- **`crates/norte-frontend/src/chrome/panelbar.rs`, `statusbar.rs` test
  data** and **`chord_es.rs`**-style fixtures (T18/T19): `Lang::Es`
  assertions and bilingual-letter-derivation test data. Per the phase's own
  rule ("Spanish text asserted by a test running under `Lang::Es`"), left
  untouched.
- **`crates/norte-cli/src/cmd/connect.rs`'s `"s" | "si" | "sí" | "y" |
  "yes"`** answer-parsing match (T21): user INPUT vocabulary, not output —
  `cli-hostkey-prompt` itself is bilingual (`[s/N]` in `es.ftl`, `[y/N]` in
  `en.ftl`), so removing the Spanish accept-words would break a Spanish
  locale user answering the Spanish-language prompt. Left as-is.
- **All plugin `help.md` files** (T25): user-facing help pages (TOML front
  matter + Markdown body, served by norte's help system), not extractable
  into Fluent as a single string, and phase 1's own exclusion list already
  puts `crates/norte-help/topics/**` out of scope for the same reason. Two
  remain in Spanish: `plugins/git-panel/help.md`, `plugins/git-status/help.md`.
  Left for a separate documentation pass, not this phase.

## Nothing went to Fluent

Every genuinely reachable TUI/window/frontend/ui-host string was already
reported "None found" by its owning task (T08–T17c: everything already goes
through `t!`/`t_in`/`ta`/`ta_in`). The only §3 findings that survived
verification were CLI-only (decision #1: inline), one `norte-core` design
choice that documents itself as deliberately untranslated (inline, reasoned
above), and a WASM plugin with no Fluent access at all (inline, reasoned
above). So no keys were added to `en.ftl`/`es.ftl` in this phase.
