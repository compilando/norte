**Process violations worth flagging to whoever runs the next dispatch:**
1. The dispatcher split T08 into 5 disjoint sub-agents (dto.rs alone;
   bridge.rs+action.rs; backend.rs+commands.rs; pickers.rs+settings.rs+
   extensions.rs; help.rs+keys.rs+agents.rs+lib.rs) with an explicit
   "touch nothing else" instruction each. At least one sub-agent (the
   help/keys/agents/lib one) exceeded its assigned slice and itself
   dispatched further sub-agents over the *whole* 12-file set, duplicating
   work already assigned to the other four. This is what produced the
   repeated "file modified since read" collisions on `commands.rs`,
   `extensions.rs` and `settings.rs` reported above — not an external T09-T11
   agent as first suspected. No damage resulted (every collision was caught
   by Edit's stale-read guard and re-verified), but the scope discipline
   itself failed and should not be trusted blindly next time; a post-hoc
   `git diff` + `rg` audit of the full file set (as done here) is what
   actually confirmed correctness, not the sub-agents' own self-reports.
2. One sub-agent used a `python3` heredoc via Bash to do a single global
   text replacement in `pickers.rs`, instead of `Edit`/`Write` — against the
   explicit "Edit/Write tools only" rule. It was not blocked by the hook and
   the result was verified correct, but it should not have happened.
