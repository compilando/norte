## 1. pub renames (not done — cross file)

Essentially **every `pub(super)` method and type name in this task is
Spanish and was left untouched**, because `controller` is one `impl Estado`
split across ~40 files (T08/T09 own the rest), and any rename has to be
coordinated across all of them in one pass, not decided file-by-file. I did
not attempt partial renames of shared names. Notable types (all `pub(super)`,
each defined in exactly one of my files but referenced from `mod.rs`'s field
declarations):

- `preview.rs`: `EstadoPreview` (fields are private → already in English:
  `shown`, `viewer`, `note`, translated `in_flight`).
- `panelplugin.rs`: `Firma`, `EstadoPanel` (fields private, left in English
  already except `kind`/`frame`/`state`/`firma`/`en_vuelo` — `firma`/`en_vuelo`
  are Spanish but private-only, kept as-is per the "propose, don't rename
  cross-file" instinct since `Firma` itself, the type, is the Spanish word).
- `diskmap.rs`: `EstadoMapa` (fields `mapa`, `pedido`, `en_vuelo` — all
  `pub(super)`, not renamed).
- `timeline.rs`: `EstadoLinea` (all fields private → renamed internally:
  `model`, `in_flight`, `requested`, `reason`, `page_error`, `retry`,
  `exhausted`, `return_to`).
- `organize.rs`: `RevisionOrganizar` (all fields private → renamed
  internally: `lines`, `first`, `seen_until`, `acknowledged`, `epoch`; `dir`,
  `moves`, `plan_hash` already English).
- `profiles.rs`: `SeleccionDeTema` (fields `nombres`, `cursor`, `previo`, all
  `pub(super)` → not renamed).
- `settings.rs`: `AjusteEscrito`, `AjusteRestablecido` (fields `nombre`,
  `valor`, `id`, `resultado`, all `pub(super)` → not renamed).
- `sums.rs`: `SumasEncoladas`, `Publicado` (the latter's fields are private
  and already English: `lines`, `asked`, `refused`; `SumasEncoladas.publicado`
  is `pub(super)`, not renamed).
- `search.rs`: `Busqueda` (fields `epoca`, `task`, `desenlace` are
  `pub(super)` → not renamed; private fields renamed internally: `abandoned`,
  `query`, `root`, `hits`, `semantic`, `cursor`, `cap`); `Hallazgo` was
  private-only → renamed to `Hit` throughout the file.

Every `pub(super)` fn (hundreds — `abrir_*`, `cerrar_*`, `aplicar_*`,
`pedir_*`, `tecla_en_*`, etc. across these 30 files) is likewise Spanish and
untouched. Recommend phase 2 treat the whole `controller/` module as one
renaming unit rather than trying to reconcile per-task proposals.

## 6. TODO(translation)

Added **7**, all for pre-existing stale/misplaced doc comments (two
consecutive `///` blocks where the first describes a different, unrelated
function than the one it ends up attached to, or a duplicated one-liner) —
found in `agents.rs` (1), `approvals.rs` (1), `gestures.rs` (1), `input.rs`
(2), `panel.rs` (1), `viewer.rs` (1), `layout.rs` (1, plus one doc comment
left with the same odd mid-sentence split as the original — see below),
`search.rs` (2). None of these are things I fixed structurally; I translated
the text faithfully in its existing (broken) shape and flagged it.

One item worth flagging explicitly for the whole-branch review: in
`layout.rs`, `poner_arbol`'s doc comment is interrupted mid-sentence by
`rehacer_reparto`'s function+doc landing in between, leaving the fragment
`"throw it away an instant later."` stranded as its own one-line comment
immediately before `poner_arbol`'s signature. I kept the same broken
structure (translated) rather than reflowing it, per "translate faithfully,
don't restructure."

Also worth a look by a human, not a translation issue: in `approvals.rs`,
`abrir_aprobacion` builds `agents_notice` (a repaint patch for the open
agents panel) but never merges it into the function's return value — this
matches the original Spanish source's behavior exactly (I verified by
re-reading: `fuera` was built and `.push`ed into but never referenced again
before the `let mut salidas = …` at the end). Looks like a latent bug
(the agents panel doesn't repaint when a new approval reassigns session
ordering), but it's pre-existing and out of scope for a translation pass —
flagging for the branch reviewer.
