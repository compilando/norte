## Bug found and fixed (not a translation task, but blocking `just t`)

`metadata.rs`'s test module (translated by the *previous* T17 agent, already
committed in `e58104a5`, not touched again by this session beyond this fix)
had two assertions that guessed an English string instead of checking the
actual `en.ftl` resource the code renders:

- `what_is_unknown_does_not_appear` and
  `the_parent_row_is_named_two_dots_and_says_where_it_leads` both asserted
  `rows[1].value == "directory"`, but `metadata-kind-dir = folder` in
  `en.ftl` — the real rendered value is `"folder"`.
- `the_parent_row_is_named_two_dots_and_says_where_it_leads` also asserted
  the third column's label was `"Target"`, but `metadata-target = Leads to`
  in `en.ftl` — the real label is `"Leads to"`.

Both fixed to match the actual Fluent output. This was failing the entire
`just t norte-frontend` run (fail-fast cancelled 867 of 1381 tests before the
fix). Confirms the report's earlier note: a word-for-word guess at an
English string is not the same as checking what the code actually renders —
worth a mention for any other file in this crate whose tests assert literal
UI text against `Lang::En`.
