## Notes on what stayed Spanish on purpose

`render.test.ts` fabricates `ViewSnapshot`/`HostCatalog`/etc. fixtures that
mirror what a real (Spanish-locale, `locale: "es"`) host would send over the
wire — labels like `"Nombre"`/`"Tamaño"`, menu titles, dialog warning text,
status messages, settings names/descriptions, help-page prose, place names,
etc. These are exactly the kind of "test fixture data that mirrors wire
payloads" the task rules say to keep, and translating them would make the
fixtures inconsistent with what the real `i18n/es.ftl` (untouched, per rules)
actually produces — several assertions (`realCatalog()["..."]`) read directly
from that file, so a mistranslated fixture would either silently diverge from
reality or break the test. Left in place, confirmed by grep after finishing
(46 lines remaining in `render.test.ts`, 2 in `session.test.ts`, 1 in
`keys.test.ts` — all inspected individually, all fixture data or an
intentional NFD/hostile-name test string).

`index.html`'s `<html lang="es">` was also left as is: it's the app's
current default UI locale, not a comment or identifier, and out of scope for
a language-of-the-source-code translation pass.

   via `grep -n "<old name>("` immediately after the edit and fixed before
   continuing. Final `npx vitest run` (264/264 passing) and `tsc --noEmit`
   confirm nothing was missed in the end state.
