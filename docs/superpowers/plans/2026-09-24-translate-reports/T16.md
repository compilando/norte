## 2. cross-file literals (kept, not translated)

- **Snapshot-pinned data.** `snapshots_ui.rs`, `layout_anchor.rs` and
  `places.rs` call `insta::assert_snapshot!`. Where the macro has **no
  explicit name** (most calls), insta derives the `.snap` filename from the
  test function's own name — so those function names were left in Spanish
  on purpose (e.g. `snapshot_navegacion`, `snapshot_modal_transfer_name`,
  `snapshot_sidebar_abierto`, `snapshot_ayuda_filtro_hostil`, …). Renaming
  them would silently break the golden file linkage. Where an explicit
  name is passed (`layout_anchor.rs`'s `"orthodox-100x30"` and
  `"preset-{name}-{w}x{h}"`), the function name is decoupled from the
  snapshot and was translated freely.
- **Rendered fixture/test data that ends up inside a `.snap` file**, verified
  with `rg -F` against `crates/norte-tui/tests/snapshots/*.snap`: directory
  and file names used across `app_base()` and friends (`casa`, `otro`,
  `docs`, `src`, `notas.txt`, `medios`, `cosa`, `enlace`, `grande.bin`),
  hotlist entries (`trabajo`, `roto`/`rota`), a custom column header
  (`"Peso"`), and typed filter text (`"copiar"`). All kept verbatim.
- **Genuine rendered UI text from the real Fluent catalogue.** Many tests
  force `norte_i18n::Lang::Es` and then assert against the *actual*
  Spanish translation the app would show (menu labels, panel names,
  status-bar text like `"pérdidas"`, `"forzado"`, `"ficheros"`, `"libres"`,
  help footer verbs `"bajar"`/`"atrás"`/`"índice ↔ texto"`, etc., in
  `snapshots_ui.rs`, `layout_anchor.rs`, `places.rs`, `theme_render.rs`,
  `viewer.rs`, `mouse.rs`). These are the product's own i18n output, not
  test prose — never touched.
- **Values produced by `norte-frontend` (not mine, not yet translated).**
  `KeymapError::WrongLayerKey { layer: "usuario" | "preset", .. }` in
  `keymap.rs` matches string literals hard-coded in
  `crates/norte-frontend/src/keymap/{layer,mod}.rs` — that crate is T18's
  (`frontend/src/{chrome,keymap,layout,navigation,ops}/`). Left as-is; **flag
  for phase 2 / T18**: when that file translates `"usuario"`/`"preset"` to
  English, `keymap.rs`'s pattern matches need the same update in the same
  commit or this test breaks.
- Similarly, `metadata.rs` asserts against `norte_frontend::metadata::sheet`'s
  output (`"carpeta"` appears in a returned Vec) — that's `norte-frontend`
  output, not mine to change.

## 7. What was *not* renamed (identifiers) — scope note

Given the size of this task (~16k Spanish-bearing lines across 27 files),
I prioritized translating every comment, doc comment, and
panic/expect/assert message (required, highest value, and what a reader
actually sees when a test fails) over renaming every private local
variable/helper. Test function names were renamed where safe (no
`insta::assert_snapshot!` dependency) and time allowed — done in
`snapshots_ui.rs`, `mouse.rs`, `layout_anchor.rs`, `places.rs`, `tree.rs`
for the more prominent ones — but **most local variables and several
private helper functions across all 27 files remain Spanish**
(e.g. `pantalla`, `fila`, `hueco`, `lineas`, `zonas`, `app_de_prueba`,
`app_con_panel`, and similar). None of these are `pub`/cross-file, so
nothing is functionally broken or blocks other tasks, but a future pass
could rename them for full compliance with "identifiers visible only
inside your file... translate."  I did not track every remaining Spanish
identifier individually; a fresh `rg` sweep for common Spanish words in
`fn`/`let` positions per file would find them quickly.
